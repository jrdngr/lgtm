# lgtm

Desktop code review for agentic development, built on `jj`.

This software is made for my personal use. If you don't want to install `jj`, `gh`, or `claude`, fork it.

You're welcome to file issues and feature requests, but I may or may not ever look at them. 

You're not welcome to file pull requests. I already spend too much time reading them. Turns out it's really fun to make your own editor and I don't want to make it unfun. Just fork it and make it your own.

This program may or may not be safe to run. Use it at your own risk.

The right panel's tabs run down its outer edge: Files; Changes, Guided, Comments, Architecture and Reports; Q&A; then Drawings and Notes. They stay when the panel is hidden: a tab opens the panel on it, and the open tab hides it. A tab's icon turns amber when something there waits on you: threads to triage or decide, open high Look items, or open questions. Comments (⌘⇧M or ⌘⇧P) holds a PR workspace's PR, its threads by stage, then your comments by file, with All, PR and Comments filters. Without a PR it holds your comments. Architecture has Generate, the repo's designs (a dot each: fresh, stale or missing; + for a new one; right-click for Show, Regenerate, Edit… and Delete), and with a review open, the score, Look items to check off, the layers, a map of the containers and the components the review changes, and History (click a commit for its change, shift-click a second to compare). Without a review it lists the system's tours, people, external systems, and containers with their components (stale ones marked). A row shows its node in the Architecture tab.

Guided Review (⌘⇧U, or New Tab › Guided Review) walks you through the code that needs a human, as an agent split it. Generate (Update once there is one) in the Guided tab of the right panel sends the send target's agent your guided-review prompt (Settings › Prompts; a repo's `.lgtm/guided.md` wins over `~/.config/lgtm/guided.md`), and it hands back chunks through lgtm's MCP `set_guided_review`. A chunk is related code from any files, plus unchanged code read alongside it, rated High, Med or Low with reason tags, a writeup, optional steps, test results and the ADRs and dev logs it bears on. Docs, boilerplate, generated code and simple implementations are left out with a reason, and any changed line the agent didn't place shows as Unlisted. The sidebar shows a bar of the lines still to approve by risk, approved in green and skipped in gray, then Context (the ADRs and dev logs, each summarized with Open), a folding section per risk (right-click one for Approve All or Skip All, a row for Approve, Skip or Clear Verdict), Commented (PR threads on code no chunk holds), Tests and Excluded by reason. A chunk opens in the Guided Review tab: its PR threads on top with their lines ringed in violet, the writeup, docs and tests, then the code. Click a changed line (shift-click to extend) and press `c` to comment, or ⇧C for a PR draft. Approve (`a`) marks the chunk's changed lines reviewed and goes to the next chunk; Change (`c`) sends the chunk and your note to the agent and goes on; Ask (`?`) pastes the chunk into the terminal for your question. Skip marks its lines with the skipped color, so the Review tab's progress agrees. Steps shows the steps beside the code, each lighting its lines (←/→). Architecture opens the Architecture tab with the Review lens on the chunk's files alone (× in its strip for the whole review). Prompts lists the prompts in lgtm terminals whose edits wrote the chunk's lines. Update keeps chunk ids, so untouched chunks keep their verdicts; a chunk whose code changed since its verdict shows Changed, with Since you reviewed and Whole chunk. Click an excluded part to read it with the agent's reason, and Promote (`p`, then 1–3) makes it a chunk at the risk you pick.

Notes (the last tab) are markdown notes kept in lgtm, in three sections: Global shows in every repo, Repo in each of the repo's workspaces, and Workspace only in its own. Global and Repo start collapsed. Each section has folders; + and the folder button next to a section's name make a note or folder at its top, and right-click a section or folder for New Note and New Folder, or a folder or note to Rename or Delete it. Drag a note onto a folder or a section to move it there, between sections too. A note opens in its own tab with the markdown editor's Editor and Rendered views (⇧⌘V) and saves as you type. The box at the top is for a quick note: Save (⌘↵) files it at the top of Workspace, named by the time, and opens it; Send (⇧⌘↵) pastes it into the send target without pressing Enter. Either clears the box, and each workspace keeps its own draft. Agents read and write notes with MCP `list_notes`, `read_note` and `write_note`.

The left panel lists the workspaces on top and the selected workspace's revisions under them (drag the split between them to resize, double-click it to fit the workspaces again): `jj log` as two-line rows (change id, description and conflict or divergent flags; then bookmarks, author and age), with jj's graph drawn beside them. The reviewed commits are tinted blue and bracketed, `@` green. Each open PR's head commit has a `#N` pill at the end of its row; click it to review the PR. A PR in the middle of a stack reviews only its own commits, from its base branch or the next open PR's bookmark below it, whichever is nearer. Right-click a pill to Review PR, Preview, Open on GitHub, Copy PR URL or Copy Bookmark Name. The workspace's PR follows the review: clicking a pill makes that PR the workspace's PR, and reviewing anything else drops it. ⌘⇧K focuses the revisions: j/k move, ⇧J/⇧K extend a range, `r` reviews the commit or range, dragging across commits brackets them as you go and reviews them, clicking the rail beside a commit reviews it, ↵ or a double-click edits it, and Esc goes back to the review. ⌘J opens the motions at the bottom of the log: `na`/`nb` make a new commit after or before the cursor's, `s` squashes the selection into its parent and keeps that commit's description, `u`/`U` undo and redo, `gf`/`gp` fetch and push, and `rm` rebases the cursor's branch onto trunk (main@origin). A prefix narrows the list, Backspace widens it and Esc closes it. Right-click a commit to review it, review from it to `@`, or edit it; right-click the Revisions header to review the PR, `@`, `@-`, trunk to `@` or any revset, or to edit the review's head. When `@` is outside the review, a banner (Review @, Edit Review Head) turns red, and so does a dot on the shown editor tab. Moving `@` keeps a review it is still in or on top of; otherwise the review goes to the checked-out PR's commits, or to `@`. Blue marks review and PRs throughout. ⇧⌘J reviews only `@`.

The review bar's progress bar splits the changed lines by mark, then lines in checked or skipped files, with the done share beside it. Hover it for the lines reviewed and left, and each part's count.

lgtm snapshots a workspace's files while it's open, so edits show up live. Workspaces you haven't opened, like an agent's, are left alone. A background snapshot that waits on another jj's lock for 15 seconds is stopped, which is safe since it hasn't written anything yet. After two in a row, the header shows jj busy and background snapshots pause there until you select the workspace, save a file in it or run a jj action there. When an action of yours waits on a lock for 10 seconds, a red banner lists the processes that have the lock open, with PID, running time and command; the action keeps waiting. Killing a jj that's only waiting is safe; afterwards run `jj workspace update-stale` in any workspace that reports stale. Quitting lgtm stops the jj processes it started.

The maximize button at the end of a pane's header (or ⇧⌘↵, Maximize Pane in its right-click menu, or a double-click on empty space in its tab strip) fills the center with that pane and hides the others; a blue line runs across the top while it does. The same button, now blue, or ⇧⌘↵ again restores every pane, and collapsed panes stay collapsed. Picking a tab in a hidden pane restores them too. ⌃` still opens the bottom panel under it.

Right-click a workspace to pin it to the top of the list or give it a color. Drag pinned workspaces to reorder them.

Everything sent to a terminal (⌘>, violet buttons, Send Path to Terminal) goes to the send target: the workspace's first terminal until you pick Pin as Send Target from another terminal tab's menu. Every terminal tab leads with a ›_, violet on the send target (whose title is violet too) and dim on the rest. When the send target closes, the first terminal still open takes over. Rename on a terminal tab's menu edits its title in place. Violet buttons also press Enter when an agent runs in the target, so it starts right away; ⌘> and Send Path only paste.

## Requirements

- [jj](https://github.com/jj-vcs/jj) 0.46 or newer: `brew install jj`
- [Claude Code](https://claude.com/claude-code), for the agents: `curl -fsSL https://claude.ai/install.sh | bash`
- [gh](https://cli.github.com), signed in, for pull requests: `brew install gh && gh auth login`

lgtm checks for these at startup and says what's missing. Only jj is required.

To build it you also need Rust, Node 22, pnpm, [just](https://github.com/casey/just), and the Xcode command line tools.

## Install

Download the .dmg from [Releases](https://github.com/jrdngr/lgtm/releases) and drag lgtm to Applications. Or build it:

```sh
git clone https://github.com/jrdngr/lgtm
cd lgtm
pnpm install
just install     # release build, copied to /Applications
```

The app's binary takes a repo path: `lgtm /path/to/repo`. Launched without one, it reopens the last repo, or shows the repo picker when that's gone. A second launch for the same repo focuses its window. Plain git repos get an offer to set up jj alongside git.

On first run, lgtm offers to register itself as an MCP server with Claude Code, so `claude` in an lgtm terminal can read and comment on the open review, and sync a PR's threads (stage, take and reply) with a review-reply workflow run in the terminal. Each write names the review's revset, or a thread's PR, and lgtm refuses it once the review has moved to another revset or to commits it hasn't loaded, or the workspace's PR has moved on. Link in the Comments panel (`l`) links the send target's agent to the whole PR review: it gets a short brief with your reply rules, and the panel shows the linked terminal, a dot while its agent works, and Unlink. The thread you last picked (a row in the Comments panel, or anywhere in a thread in the review) is the one you're on: it shows a violet terminal mark, and the hook adds it to each prompt you send there, whole the first time and by name after. Talk (the ›_ button in a thread's header, or ⌘>) picks the thread and focuses the linked terminal, linking one first if none is. The agent can set takes, move threads and suggest replies on any thread, but only you mark a reply ready; a suggestion shows under the reply with Use and Dismiss and a violet dot on its row, and a reply it gives a thread that already has one comes as a suggestion. Each exchange is filed under the thread you were on when you sent it, in the thread's folded Chat row (Show Chat in a row's menu opens it). Linking another terminal, Unlink, closing the terminal or ending its session drops the link, and the old agent hears so on its next prompt. Review next to a reply's Edit sends the thread, the reply and your reply rules to the linked terminal (or the send target), and the agent suggests a better reply. On a new, untriaged thread, Triage there sends it with your reply rules, and the agent sets its take and first reply; Triage N in the Comments panel sends every new thread to the linked terminal, or the send target when none is linked. Send N, in the Comments panel and in the review's header left of the marks, sends every open comment you haven't sent yet to the linked terminal, or the send target, in one go; the header shows it only while there are some, and a comment edited after sending counts as unsent again. Questions it asks (like a qqueue session) open in the Q&A tab, talking one over in the terminal can rewrite it there, and Answers sends your answers back to the terminal that asked. That agent also runs the tab's steps: after an answer that others depend on, Discuss and ⓘ on an option, and asking a question again after a discussion each paste a short prompt there and press Enter, waiting while the agent is busy. A discussion reply lands in the question's card when the agent finishes. If that agent is gone, the send target's agent takes the session over. Start Q&A sends a session you write in lgtm (its prompt, plus any Read first files dropped from the Files tree or Finder, or picked with Add) to the send target, and its questions come back the same way. The Architecture tab (New Tab › Architecture, or `g` in a review) maps the workspace's whole system from its imports, as C4 context, containers, components and one component's symbols (⌘-click, double-click, a card's chevron or a click on the focused node to drill in; the crumbs, the depth stepper or Backspace to go up; Back and Forward in the bar, ⌃- and ⌃⇧-, or the mouse's back and forward buttons to retrace where you went, with what was selected there; drag to pan, scroll or pinch to zoom). Containers show their biggest components as tiles; inside one, the other containers it talks to sit at the right edge as doors. A system with more than five containers shows them in groups: the ones Describe wrote, or else each container's parent folder. Context then shows the groups inside the system, Containers shows each group as a frame of small container cards with one faint line per pair of groups (hover a card for its own edges), and drilling into a group shows only its containers, with the other groups as doors. Long side columns wrap into columns about as tall as the system. At rest each edge is a faint line. Hover a node to draw its edges with their labels and fade the nodes off them, or hover an edge to draw it alone. Click a node to collapse the canvas into it, what uses it and what it uses, doors and external systems included (click a neighbor to move, the background or Esc to go back). Each wire's label sits by its neighbor; hover a neighbor, wire or label to see that wire alone with its whole label. The side panel shows what a node holds and talks to, and for a component the files to start in, its most used symbols, and what it uses and is used by. Click an edge for its import sites and what it imports. Symbols (the fourth level, or Symbols on a component) shows the component's symbols by file, with the components that call in on the left and those it calls on the right, and a faint line between each pair of files that call each other. Hover a symbol or component to draw its calls; click one to collapse the canvas into it, its callers and its calls (click a neighbor to move, the background or Esc to go back). A symbol's panel shows its signature, Open, its callers and its calls. Right-click a component for Symbols, Tour, Trace To…, Trace From…, Show in Files and Ask (⌘> asks about the selection). Find (`/`) jumps to a component, file or symbol (⌘Enter opens the file). Trace (with a node selected, it starts from that node) swaps the tools for From and To fields that search every container, component, person and external system at any level (↑/↓, Enter; clicking a node fills the field being picked; ⇄ swaps the ends; Esc or × ends it). With both ends set, the path draws straight from left to right, each hop numbered with its file and line or relation; All paths lists the ones up to two hops longer, and Show on map draws the path over the map with its hops in the side panel. With a review open, the Review toggle lays the review over the map: changed components in amber with their added lines in green and removed in red, new ones in green, impacted ones dashed, new imports in green and removed ones dashed red, and a red mark on anything with Look items; containers and components the review neither changes nor impacts are hidden (or faded, from View). A strip under the bar shows the counts, Transitive, the commits picked in History (× for the whole review) and what's left to look at (click it to flash the Look items in the sidebar), and the side panel adds the changed files, Look items and the changed components inside a container. View (in the bar) picks what the map shows: untracked files, tests and generated code (all hidden by default), small containers (fewer than three files), people and external systems, and groups; Edge labels On, Hover (a focused node's labels show only for the hovered or selected wire) or Off; and, with a review open, whether the Review toggle hides or fades unaffected nodes. The choices are kept per repo, and Describe sees the same map. Generate (in the bar and the sidebar) lists Description and, with a review open, Assessment, each Fresh, Stale or Missing, with the stale and missing ones checked; it spins while it builds the prompt, then sends one prompt for the checked ones to the send target and presses Enter when an agent runs there, and an amber dot on it means something is stale or missing. The description gives names, descriptions, people, external systems and the tiers components sit in, and the Architecture tab opens; components changed since show as stale. Until there is one, or once it's stale, a pill on the map says Not described or Description stale, with Describe. The assessment gives a score, risk, layers and items to look at, replacing the last assessment of that revset in that workspace; lgtm refuses one handed back after the review moved to other commits, and once the revset moves on it shows as Stale. Tours lists the Overview, Every feature, and each container's and component's tour, which goes from the container down to the component, who uses it, its files, its symbols and what it uses (←/→ to step). Each has Play, or Write Tour, which asks the send target to write it; right-click one for Rewrite Tour. Designs map spec files the same way: Code | Design in the bar switches the tab between the code and a design, the design's name opens a picker (each row shows its bookmark, or its change id and description, file count, Fresh, Stale or Missing, and how many parts differ, plus New Design…), and Over code lays the design over the code's map (off, the design shows alone). New Design… takes a name, a revision (`@` by default; any change id, bookmark or revset of one commit), files and folders (Add… searches the revision's files, or drop them from the Files tree or Finder) and a prompt to scope it, like one concept or some phases; Generate (⌘↵) saves it and sends the send target's agent a prompt to read those files at the revision's commit and map them, with the code's map to compare against. Files and prompt are optional: without files, Create (⌘↵) saves an empty design that opens in Edit, to draw on yourself or through an agent, and Edit… on it in the sidebar adds files to generate from later. Until it's generated, a design shows its drawing alone. A design keeps a bookmark's name, or else the change id, so rewording, rebasing or moving `@` doesn't lose it. It goes stale when one of its own files changes there, and missing until it's generated or when its revision or files are gone. Over code, new parts are dashed violet, changed ones amber, removed ones dashed red and struck through, and code containers the design leaves alone show plain; once some of the design is built, parts show ✓, Planned or Differs instead, and the bar counts them. Edges are faint lines until hovered or selected, which draws them in their color with their label, and clicking a part collapses the map into it and what it talks to, like the code's map. The fourth level is Interfaces: a component's cards list the APIs, events and functions the spec names, and drilling in shows each with what calls it and what it calls. The side panel quotes the spec lines behind a part (click one to open the file at that line), what it talks to and replaces, where the code differs, and Open spec or Update spec, which asks the agent to bring the spec in line with the code. A repo without code opens straight on its first design. An agent can make one too: lgtm's MCP `create_design` takes a name, revision (`@` by default; `bookmark` still works), files and prompt, shows the design and hands back the instructions to map it, or without files makes an empty design to draw on; `list_designs` and `design_instructions` let it find and remap one. Whenever an agent makes or maps a design, the Architecture tab opens on it. Edit (`e`, in the bar) puts a design's map on the drawing canvas, and each level of it keeps its own drawing. Its parts are locked: you can move, color, frame and tag them, but not edit or remove them. Everything else works as in a drawing, plus a part's color holding at every level, an edge's line (Solid, Dashed or Dotted, Thin or Thick, Curved or Elbow, and a handle to bend it; a styled edge always shows with its label) and Reset Layout. The first move pins every part where it is; parts added later land near what they link to with a blue dot until you move them, and Reset Layout goes back to the automatic layout. Esc leaves Edit. Drawings (the Drawings tab in the right panel, ⌘⇧X for a new one) are the repo's own diagrams, kept in lgtm. New asks for a name and opens the drawing in a tab; a row shows its tags and when it last changed, and right-click it to Rename or Delete. The tools at the bottom are Select (`v`), Rectangle (`r`), Ellipse (`o`), Diamond (`d`), Arrow (`a`), Line (`l`), Text (`t`), Sticky note (`n`) and Frame (`f`). Drag to draw a shape or click for a default one, then type its text (Enter or a double-click edits it again); drag a selected shape's corners to resize it. Arrows and lines stick to shapes, notes, frames and parts, ⌥ on drop leaves an end free. Frame groups what you drag it around. Click to select (shift adds; drag on the background to select an area), drag to move (hold space to pan), and use the bar over the selection: colors, Fill or Outline, Solid or Dashed, Group (⌘G) and Ungroup (⇧⌘G), a frame's name, a note's size, and Remove. Frames nest; dropping something into a frame moves it in, and out of one moves it out. Tags are numbered pointers for talking to an agent: press 0 to 9 with one thing selected (again to take it off), or drag a chip from the tray, and the tag snaps to that thing's corner. Each drawing, and each level of a design, has its own tags, and Clear tags removes them. Export (in a drawing's bar) saves SVG, PNG or JSON, or copies a PNG. ⌘Z and ⇧⌘Z undo and redo, and Delete removes. Agents read the canvas you last looked at with MCP `current_canvas` (its elements, your selection and your tags, so "move 3 under 5" works), change a drawing or design with `edit_canvas`, and find or make drawings with `list_drawings` and `create_drawing`; after one draws, a strip says how many changes it made, with Undo and Show. ⌘-click a link in markdown (editor or rendered) to open it: web addresses in the browser, repo paths in an editor tab. A `#anchor`, alone or after a path, goes to that heading (GitHub's ids), element `id` or line (`#L12`), in the editor or rendered view the tab is in. It also adds Claude Code hooks to `~/.claude/settings.json` (they do nothing outside lgtm), so each workspace in the sidebar shows its most urgent agent: needs input, failed, stalled (no output for 3 minutes), working, done, idle, or none. Hovering that mark lists each agent with how long it's been in its state, and clicking one brings up its tab. A tab running an agent shows the same mark before its title. A terminal tab takes its title from Claude Code's session unless you rename it, and a Claude Code session still open when lgtm closes resumes (the Claude command with `--resume`) in its terminal when lgtm opens again. Any agent can publish review findings to a report, with its own suggested fixes if it has them, and checked findings or fixes go back to a terminal: the Reports panel keeps the report you describe, and Create Report sends it with instructions to publish here. Each report has an id (`R12`, or a name you give it with Rename…) that you tell the agent, and publishing again under the same reviewer name replaces that reviewer's findings.

## Commands

```sh
lgtm [repo]               # open a repo, or the repo picker
lgtm gc [--force] [repo]  # remove leftover workspace directories, forget workspaces whose directory is gone
                          # (workspaces whose repo can't be found are kept unless --force)
lgtm mcp                  # the MCP server Claude Code starts; you don't run it yourself
```

## Develop

```sh
pnpm install
just dev         # hot reload; shows the repo picker
just go          # jj git fetch, jj new main@origin, then just dev
just test        # tsc + biome, vitest, cargo test (the Rust tests run jj)
just build       # release binary and .app
just install     # just build, then copy the .app to /Applications
just run [repo]  # run the built .app (with its Dock icon)
just gc [repo]   # lgtm gc with the release build
just bump 0.2.0  # set the app version before a release
```

To release: `just bump <version>`, push, then run the Release workflow in GitHub Actions. It builds a signed, notarized universal .dmg into a draft release to publish.

Debug builds regenerate `src/bindings.ts` from the Rust commands. `cargo test` fails if it's stale; rerun with `UPDATE_BINDINGS=1` to refresh it.

## Config

App settings are in `~/.config/lgtm/settings.toml` (lgtm › Settings…, ⌘,). The Claude command (an alias like `cc` works, since the terminal's shell runs it) starts Claude Code in a new Claude tab (New Tab › Claude) and resumes sessions. lgtm also runs it to check Claude Code's version and register its MCP server. Prompt overrides go in `~/.config/lgtm/`.

Optional, in the repo at `.lgtm/config.toml`. lgtm reads it from the review's base, so the changes under review can't change it:

```toml
# Files to skip: they start collapsed and count as done.
skip = ["*.lock", "**/generated/**"]

[anchor]
window = 2       # context lines above and below a marked line
threshold = 0.5  # minimum context score for a duplicate line to match
```

An executable `.lgtm/setup` runs in the first terminal of each new workspace. lgtm shows the whole script and asks before running it the first time, and again whenever it changes; Skip opens a plain shell, and a script that changes while it asks isn't run. A script over 64 KiB, or not UTF-8 text, isn't shown or run. It never runs for a pull request's workspace.
