# Writing the result

Once every question is decided, you write what the decisions call for into the repository:
code, docs, config, tests, whatever the prompt asks for, wherever this repo keeps them.

## Planning

- A plan lists each file you'd create, edit or delete, what changes in it, and the decisions
  it follows from (their ids).
- Follow the repo's existing layout and conventions. Don't invent a folder when the repo
  already has a place for the thing.
- Keep each change to a line or two. The plan is for reading before you write, not a draft.

## Applying

- Do what the decisions say. A note with an answer is part of the answer.
- When there's a plan, follow it, and my comments on it override it.
- Change only what the prompt and decisions call for. Don't refactor around it.
- Match the surrounding code's style, naming and comment density.
- When you're done, say in a short paragraph what you changed, naming the files.
